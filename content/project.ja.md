Skyloom は、ブラウザだけで動くバーチャル・ドローンショー・スタジオです。フォーメーションをデザインすると、クアッドコプターの編隊がそれをどう飛ぶかをアプリが計画し、その結果を観客席から、上空から、あるいはショーの下を歩きながらリアルタイムで見ることができます。

何もアップロードされず、アカウントも不要です。このページでは、プロジェクトの内容と作りを説明します。

## できること

| 機能 | 内容 |
| --- | --- |
| ホームのライブショー | 編隊が発進デッキから離陸してショーを飛びます。横のパネルの操作は、飛行中のショーにそのまま反映されます。 |
| 9つの内蔵ショー | Sakura Night、Wings、日本の夜、Neon Tokyo、Cosmos、Aurora、New Year、Ocean、Gold Gala。 |
| 入力して作る | 言葉を入力して Enter。形の名前（heart、galaxy、桜）はその形に、それ以外は夜空の文字になります。 |
| あらゆる文字 | ラテン文字は立体の文字に。日本語・中国語・韓国語・ミャンマー語は、等間隔に並んだ平面のサインになります。 |
| 自分のファイル | 画像（PNG、JPEG、WebP）、線画アイコンを含む SVG、`.glb` の3Dモデル。 |
| モデルのアニメーション | アニメーションの任意のポーズを使うか、連続するフォーメーションとして再生できます。 |
| スタジオ | タイムライン、フォーメーションごとのタイミングとトランジション、カメラショット、元に戻す／やり直し、プリセット、共有リンク、画像・動画の書き出し。 |
| 視点 | 観客、ウォーク（一人称。スマートフォンではタッチジョイスティック）、クローズアップ、正面、ロー、トップ、オービット。 |
| 環境 | 草原、湖畔、都市、フェスティバル、オーロラ、深宇宙、ブラックアウト。星、霧、花火、会場照明つき。 |
| 言語 | 英語、日本語、ミャンマー語。 |

## ドローン

すべてのドローンは光の点ではなく3Dのクアッドコプターです。キャノピー、バッテリー、4本のアーム、モーター、交互に逆回転する2枚羽根のプロペラ、着陸用スキッド、そして機体下の LED を1つ備えています。

- **ライティング。** 既定では機体全体がその色で光り、観客席から見やすくなります。*リアルなライティング* をオンにすると、機体は暗いカーボンになり、自分のランプだけで照らされ、距離による減衰と陰影がつき、プロペラが光を受けます。
- **姿勢。** クアッドコプターは傾くことでしか加速できません。各機は加速度に応じた角度だけ傾き、その姿勢になるまで少し時間がかかります。
- **色の変更** は一斉に切り替わるのではなく、編隊を横切って1機ずつ広がります。
- **着陸。** デッキ上のドローンは、表示サイズにかかわらず正しい高さでスキッドの上に立ちます。
- **一時停止は本当に停止。** ホバリングの揺れやフォーメーションの動きはショーの時計で動くため、一時停止中の編隊は静止します。

## ショーの計画のしかた

1. **サンプリング。** 各フォーメーションソースが入力を点に変えます。1点が1機で、色は元の素材から取ります。
2. **フィットと間隔。** 点をショー空間に収め、すべての機体が安全間隔を保てるまで押し広げます。
3. **割り当て。** 各機に最も近い空きの点を割り当て、総飛行距離が短くなるよう入れ替えを試します。
4. **経路計画。** どの機体も最高速度・加速度の制限を超えなくなるまでタイミングを延ばします。近づきすぎる経路には迂回を加えます。
5. **飛行。** 同じ経路関数が GPU、CPU フォールバック、プランナーで動くため、検証したものがそのまま表示されます。

フォーメーションをクリックしても、動画のように再生位置が飛ぶことはありません。編隊は各機の現在位置から、勢いを保ったまま新しい経路へ組み替わります。

## ファイルは端末に残ります

ウェブページにはファイルの場所が知らされないため、Skyloom はファイルを*リンク*します。

- Chromium 系ブラウザでは、ディスク上のファイルへのハンドルを保持します。コピーは作られず、毎回最新の内容を読み込みます。
- Safari と Firefox では、ブラウザの IndexedDB にコピーを保存します。実用上のサイズ制限はありません。

ショー自体が保存するのは小さな ID とファイル名だけです。リンクしたファイルが移動・削除された場合や、別の端末でショーを開いた場合は、代わりにリングが飛び、**ファイルを選び直す** ボタンが表示されます。ブラウザの再起動後、Chromium は読み取りの **許可** をもう一度求めます。これはブラウザの仕様で、不具合ではありません。

対応するモデル形式：バイナリの `.glb`（Draco・meshopt 圧縮を含む）。複数ファイルの `.gltf`、FBX、OBJ には対応していません。`.glb` で書き出してください。

## コードが守る設計ルール

- **変更の方法は1つだけ。** すべてのユーザー操作は、単一のディスパッチャーを通る型付きコマンドです。コンポーネントがストアに直接書き込むことはありません。
- **新しいフォーメーションはプラグイン。** ソースは zod スキーマと `generate` 関数を宣言するだけで、設定フォームはスキーマから生成されます。
- **制限の定義は1か所。** 機体数は1つの表から決まり、端末に合わせて調整されます。数値のハードコードはありません。
- **保存された状態は読み込みのたびに再検証** されるため、古いバージョンで保存したショーでも設定が欠けることはありません。
- **まずライブラリを使う。** 独自コードはつなぎ役か、どのライブラリにもないものだけで、その理由は `DECISIONS.md` に記録しています。

## 知っておきたい制限

- デザインと可視化のためのツールであり、飛行制御ソフトではありません。
- 共有リンクにはリンクしたファイルは含まれません。受け取った人はファイルの場所を尋ねられます。
- 機体数は端末のクラスごとに上限（600〜3,000機）があり、フレームレートが落ちると自動的に減ります。
- ラテン文字以外の文字のフォーメーションは、端末にインストールされているフォントを使います。
